# Mada Mobile — Repository Rules

This is an Expo Router + TypeScript application in the existing Mada pnpm workspace. Preserve Android/iOS compatibility and mobile-first behavior.

## Read before implementation

- Before changing UI, navigation, typography, auth, roles, or permissions, read [`../../docs/mobile-ux/MOBILE_FOUNDATION_RULES_AR.md`](../../docs/mobile-ux/MOBILE_FOUNDATION_RULES_AR.md) and [`../../docs/mobile-ux/UX_HANDOFF_AR.md`](../../docs/mobile-ux/UX_HANDOFF_AR.md).
- The rules document is the implementation contract. The image references are visual guidance only; do not copy their sample names, dates, scores, counts, or fake states into product data.

## Expo SDK and commands

- Read the Expo major version in `package.json` before using Expo/React Native APIs. For SDK 57, consult the versioned reference: <https://docs.expo.dev/versions/v57.0.0/>. Fetch the relevant SDK-specific page before relying on an API.
- Use `pnpm --filter @mada/mobile exec expo install <package>` to add Expo-compatible dependencies; do not use `pnpm add` for app dependencies.
- Run `pnpm --filter @mada/mobile lint` and `pnpm --filter @mada/mobile typecheck` before finishing mobile changes.
- Native projects are generated by Expo prebuild. Do not create or hand-edit `ios/` or `android/` directories.

## Visual system

- `packages/mada-tokens/tokens.css` and `client/src/components/MadaTheme.css` are the web visual reference. Keep `src/theme/tokens.ts` in parity when tokens change.
- Use Cairo for Arabic and Inter for Latin/numeric labels. Fonts are bundled locally and loaded at the root. All UI text must use `src/components/MadaText.tsx`; avoid direct React Native `Text` imports in screens/components.
- Keep RTL as the default; explicitly use LTR/Inter for phone numbers, identifiers, and other Latin values.
- Reuse `AppUi` primitives and maintain the agreed priority-first Home hierarchy. Do not put permission diagnostics on Home.

## Architecture and authorization

- `src/app/` contains thin Expo Router routes/layouts. Put API access in `src/api/`, session state in `src/auth/`, route/permission policy in `src/authorization/`, and reusable UI in `src/components/`. Put new domain workflows under `src/features/<feature>/` as they are implemented.
- The server's authenticated `GET /api/v1/me` response is authoritative for role, scope, and permission keys. Match role codes and permission keys to backend contracts; never invent or locally grant them.
- The first mobile role surface is R04. Login sends `accountType: "staff"` internally; this is an authentication path, not a user-selected role. Do not add local role or membership switching without an explicit backend contract.
- Guard routes and hide unavailable tabs for UX, but assume the backend must independently authorize every record and action. Default deny on unknown roles/permissions; never send client-selected `academyId`/`branchId` as authority.
- Store refresh credentials only through `expo-secure-store`; do not log tokens or store them in unencrypted AsyncStorage.
- Do not fabricate tasks, sessions, notifications, scores, or counts. Keep loading/empty/error/forbidden states distinct and identify live data sources.

## Change acceptance

Run mobile lint/typecheck, repository tests/check/build, and Expo dependency checks as appropriate. For navigation, font, or native-module changes, export both Android and iOS bundles and review Arabic RTL, font loading, and safe areas. Web preview alone is not native acceptance.
