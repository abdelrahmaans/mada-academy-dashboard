# المعمارية التقنية وهيكل المشروع (Mada Architecture & Monorepo Guide)

يقوم مشروع **مدى (Mada Academy)** على معمارية Monorepo حديثة تضم تطبيقات الواجهة والسيرفر والرموز المشتركة داخل مستودع واحد مُدار بواسطة `pnpm workspaces`.

---

## 1. شجرة وهيكل المونوريبو (Monorepo Layout)

```text
mada-academy-dashboard/
├── apps/
│   └── landing/                 # صفحة الهبوط والتسويق واستقبال طلبات الـ Demo
├── backend/
│   ├── MadaAcademy.Api/         # تطبيق .NET 10 Web API الرئيسي
│   ├── MadaAcademy.Api.IntegrationTests/ # اختبارات التكامل وقواعد البيانات
│   ├── MadaAcademy.sln          # Solution الباك إند
│   └── scripts/                 # سكربتات التهيئة وقواعد البيانات
├── client/                      # داشبورد العمليات الأساسي (React 19 + TypeScript + Vite)
│   ├── public/                  # الأصول الثابتة والأيقونات
│   └── src/
│       ├── components/          # المكونات المشتركة، السايدبارز، والموديولات
│       ├── contexts/            # سياقات الحالة (AuthContext, RoleScopeContext)
│       ├── hooks/               # Custom React Hooks
│       ├── lib/                 # عميل الـ API، الصلاحيات، ودوال الحساب
│       ├── pages/               # شاشات ومسارات الأدوار
│       └── styles/              # تنسيقات ومحددات الثيم الموحد
├── client-angular/              # تطبيق موازٍ بإطار Angular للتوافق المؤسسي
├── packages/
│   └── mada-tokens/             # حزمة رموز التصميم الموحدة (Design Tokens & Colors)
├── shared/                      # ثوابت وعقود مشتركة بين الواجهة والسيرفر
├── supabase/                    # سكربتات تهجير قاعدة بيانات PostgreSQL سحابياً
├── docs/                        # مركز التوثيق الفني والمصفوفات والأدلة
│   └── archive/                 # الخطط والتقارير التاريخية المؤرشفة
├── e2e/                         # اختبارات الأتمتة الشاملة (Playwright E2E)
├── patches/                     # ترقيعات الـ pnpm للحزم الخارجية (مثل wouter)
└── scripts/                     # سكربتات التشغيل والبناء المحلية
```

## 2. مكدس التقنيات (Technology Stack)

### الواجهة الأمامية (Frontend Dashboard):
* **الإطار الأساسي:** React 19 مع TypeScript.
* **أداة البناء والتطوير:** Vite فائقة السرعة.
* **التنقل والراوتينج:** `wouter` مع دعم الـ Hash المزدوج للتنقل العميق.
* **التصميم وتجربة المستخدم:**
  * تصميم عربي أصيل يدعم اتجاه اليمين لليسار (`dir="rtl"`) كمعيار افتراضي.
  * لوحة ألوان دقيقة عبر HSL Design Tokens مستخرجة من `@mada/tokens`.
  * خطوط عربية حديثة وعناصر تحكم Radix UI تفاعلية.
  * مكونات إشعار سريعة وتنبيهات تفاعلية عبر `sonner`.

### الباك إند وقواعد البيانات (Backend & Persistence):
* **الإطار الأساسي:** ASP.NET Core (.NET 10) Web API.
* **قاعدة البيانات:** PostgreSQL مع دعم schemas منفصلة لتعدد المستأجرين (Tenant Isolation).
* **الوصول للبيانات:** Entity Framework Core مع تتبع سجلات التدقيق (Audit Trails).
* **الأمان والمصادقة:**
  * JWT Bearer Tokens مع التحقق الصارم من الـ Claims.
  * تشفير كلمات المرور باستخدام BCrypt.
  * آلية دقيقة لتسجيل الدخول بأرقام الهواتف المحققة (Exact-phone lookup) لجمهور الأسر والطلاب.

## 3. مبادئ الحماية وتعدد المستأجرين (Multi-Tenancy & Isolation Guardrails)

1. **عزل المستأجر والفروع (Tenant & Branch Scoping):**
   كل استعلام (Query) أو تعديل (Mutation) على مستوى الباك إند يتضمن شرط المستأجر `TenantId` والفرع `BranchId` بشكل إجباري ومستخرج من توكن المصادقة المشفر وليس من مدخلات العميل.
2. **عزل بيانات أولياء الأمور والطلاب:**
   حسابات `consumer` لا تستطيع الاستعلام عن أي معرف `StudentId` ما لم يكن مرتبطاً صراحة بجدول الوصاية والأسرة `FamilyStudentLink`.
3. **حماية التقييمات الأكاديمية:**
   تقييمات الطلاب المدخلة من المدرب تظل في حالة مسودة `DRAFT` أو قيد المراجعة `SUBMITTED` ولا يمكن لأي ولي أمر أو طالب رؤيتها حتى يعتمدها رئيس المدربين وتصبح `PUBLISHED`.
4. **حماية الفواتير والتحصيل:**
   السكرتارية تمتلك حق إنشاء فواتير وتسجيل مدفوعات نقدية، ولكنها لا تملك صلاحية تعديل فواتير مسددة أو رؤية المصروفات الشاملة المقتصرة على المحاسب والمالك.
