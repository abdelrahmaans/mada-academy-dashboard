# مصفوفة شاشات Mada Mobile والـAPI والصلاحيات

**آخر تحقق من المصدر:** 2026-10-13 — الفرع `feat/mobile-expo-role-auth`، commit `a3ac15e`
**النطاق:** تطبيق Expo الحالي على Android وiOS. المساحة الوحيدة المفعّلة في v1 هي المدرب `R04_INSTRUCTOR`.

## كيف تقرأ المصفوفة؟

- **صلاحية التطبيق** تعني شرط إظهار route أو الإجراء في `apps/mobile/src/authorization/routeAccess.ts`، وتُحمّل مفاتيحه من `GET /api/v1/me`.
- **حماية Backend** هي ما يفرضه الخادم فعلًا: سياسات المصادقة، الدور، المؤسسة/الفرع، إسناد الجلسة، أو صلاحيات إشراف المجموعة. قد لا يكون هذا الفحص تنفيذًا حرفيًا لنفس permission key؛ لذلك لا نعتبر إخفاء الزر حمايةً للبيانات.
- **الحالة** تفرّق بين route موجودة وبين API موجود في الخادم. وجود endpoint لا يعني أن الموبايل يستدعيه بالفعل.
- كل المسارات أدناه نسبية إلى `/api/v1` ما لم يُذكر العكس.

## 3. صلاحيات شاشة مراجعة التقييمات — خارج v1

هذه ليست شاشة المدرب التي تكتب التقييم؛ إنها شاشة اعتماد/إرجاع تقييم، ولا يوجد لها route Mobile حاليًا:

| الإجراء                          | Endpoint                                                      | صلاحية/شرط متوقع                                                                                                  | تحقق Backend الحالي                                                                             |
| -------------------------------- | ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| قائمة التقييمات المرسلة للمراجعة | `GET /scheduling/evaluation-reviews`                          | أساسًا `R03_HEAD_INSTRUCTORS` مع `evaluations.review` وإسناد إشرافي صالح                                          | يقبل handler الدور R03 أو R04؛ ويلزم إسناد مجموعة بصلاحية قراءة/قرار.                           |
| ملخص حالات المراجعة              | `GET /scheduling/evaluation-status-summary`                   | لا يُستخدم كقائمة مهام تقييم للمدرب؛ هو summary لمسار المراجعة                                                    | يفحص دور الوصول للمراجعة والنطاق والإسناد الإشرافي.                                             |
| اعتماد/إرجاع للتعديل             | `POST /scheduling/evaluation-reviews/{evaluationId}/decision` | قرار المراجع يتطلب صلاحية قرار مراجعة وإسنادًا يسمح بـ`CanDecideEvaluations`؛ R03 هو الدور المقصود في v1 الإشرافي | handler يتحقق من قرار `PUBLISH` أو `REQUEST_CHANGES`، ومن نطاق التقييم والإسناد وصلاحية القرار. |

> **تنبيه اتساق:** شروط هذه handlers تعتمد على role وassignment flags في مواضع، بينما `RoleCatalog` يعرض permission keys. قبل بناء شاشة المراجعة أو تقييمات المدرب، يجب أن يتفق العقد والواجهة والـBackend على سياسة واحدة، وألا نعامل اسم الدور وحده كبديل عن الصلاحية الدقيقة.

## 5. الخلاصة التشغيلية

**الموجود اليوم:** هيكل Expo والتنقل، دخول staff بكلمة مرور، استعادة الجلسة، `/me`، عرض هوية R04، حراسة tabs/routes، وواجهات Home/Schedule/Tasks/Account.
**غير الموجود اليوم:** استدعاءات Mobile للبيانات التشغيلية، شاشة تفاصيل الجلسة والحضور والتقييم، notification center، وqueue مجمّع للمهام/الأولويات.
**المبدأ:** الواجهة تستخدم permission keys لتوجيه المستخدم، لكن Backend يظل صاحب القرار النهائي على الدور والنطاق والإسناد وكل mutation.

## ملاحظة أمنية ملحقة — صلاحية قراءة الجلسات

عند تتبع الحماية في المصدر، سياسة `staff` في `AuthenticationRegistration.cs` تتحقق من تسجيل الدخول و`accountType=staff` فقط. ومسارا `GET /api/v1/sessions` و`GET /api/v1/sessions/{sessionId}` لا يظهر فيهما فحص صريح لمفتاح `sessions.read` أو `sessions.assigned.read`؛ يعتمد التنفيذ على نطاق المؤسسة/الفرع، ويضيف فلترة الإسناد لـR04 وR03. لذلك قد يتمكن دور موظف آخر داخل نطاقه من قراءة جلسات رغم أن `RoleCatalog` لا يمنحه `sessions.read`، بحسب نطاق عضويته.

هذا **عدم تطابق RBAC يحتاج تحققًا وإصلاحًا في Backend قبل الإطلاق**؛ إخفاء تبويب الجدول عن الدور لا يحمي endpoint. احتفظوا بفلترة الإسناد الحالية للمدرب، وأضيفوا فحص صلاحية/دور صريحًا لكل endpoint، مع اختبارات سلبية تثبت أن R01/R07 مثلًا لا يقرآن جلسات إذا لم تمنحهما سياسة المنتج ذلك. لا نغيّر هذا السلوك تلقائيًا ضمن توثيق المصفوفة، لأنه قرار تفويض Backend.
